# 细胞排除账本

设计要求，尚未统一接入执行代码。每个实际改变细胞集合的步骤必须记账；记账是该步骤内的程序执行，与结果一起验收，不新增独立调度任务或模型调用。

## 每一步都要交代去向

| 环节 | 需要记账的内容 |
|---|---|
| 上游标准化结果接入 | 接续已有逐细胞排除记录及来源。若标准化之前缺少逐细胞记录，明确标注追溯起点和缺口，不编造 cell IDs 或宣称全程守恒。 |
| organize | 默认分配全部已接受输入，不新增 QC 删除。已获授权的来源不纳入或显式排除，需要枚举相应细胞和原因；单纯拆分、合并、重命名用来源映射对账，不记删除。过滤条件漏掉细胞是错误，不能自动变成“排除”。 |
| per-sample 子集准备 | 执行已确认的输入排除规则时逐细胞记账；继承已有账本。未映射细胞必须报错，不能默默漏掉。 |
| 单样本 QC | 每个实际过滤动作记录受影响细胞及原因，沿用 qc_removed.csv 的证据；最终汇总所有实际排除。样本全部过滤为空也必须交付完整账本。 |
| 单样本模型注释 | keep/flag/drop 中的 drop 只是提案，保存决定和证据，不计入实际排除；后续真正应用时再记账并引用该提案。 |
| cross-sample 样本纳入 | 一个样本被明确决定不纳入时，将其经过 OSP 后仍存活的细胞全部记为本步排除，注明样本及纳入决定理由。已在 OSP 排除的细胞不重复计数。 |
| cross-sample 数值计算及工具 | DEG/QC 的临时计算掩码记录为证据范围，不计实际排除。若任何数值步骤确实过滤输入细胞，必须在该过滤动作记账，不能藏在计算函数里。 |
| cross-sample 应用决定 | 按 cell ID 合并实际生效的预注释、类型及质量删除理由；一个细胞只计一次，多个原因全部保留。 |
| zoom-in 谱系计算及工具 | 子集划分、临时 DEG 掩码和子聚类不算删除；任何实际过滤依上述规则记录。未 zoom 的谱系细胞原样进入汇总。 |
| zoom-in 应用决定 | 记录 2.0 质量决定实际去除的细胞，包括解离应激/濒死原因，附 1.0 类型群与 2.0 质量群。reassign 是改归属，单独记录且继续保留，不计删除。 |
| 汇总、迭代与最终发布 | 保留各步账本引用，按当前有效执行链汇总实际排除。下一轮只接收保留细胞，不能将历史删除再记一遍。清理中间文件不是细胞排除。 |

## 一条记录需要什么

账本可采用压缩 CSV：每个实际排除步骤写一个 `cell_exclusions.csv.gz`，一行对应一个被排除的细胞；已有 qc_removed.csv / annotation_removed.csv 等文件保留兼容，用统一字段或转换视图接入，不要求每轮复制全部历史账本。

- **细胞身份**：稳定 cell_uid，以及 source_id、source_cell_id；保留原始字符串，跨来源相同 barcode 不能混同。改名、分割和合并不改变来源身份。
- **发生位置**：run_id、输入/计算版本、round（不适用时为空）、stage、operation、sample/analysis unit/lineage（适用时）、attempt 和时间。
- **原因**：非空 reason_code 和可读 reason，允许同一细胞有多个原因；附规则/参数或已接受模型决定的引用、证据文件与版本。不能只写“filtered”或“QC failed”。
- **决定归属**：规则、模型或用户显式决定；记录决定来源与实际应用位置，两者可能不同。
- **局部身份**：相关 clustering key、cluster ID；zoom-in 同时记录 1.0 类型与 2.0 质控归属。

实际排除账本只收录已经应用的排除。提案、临时计算排除、改归属和保留例外各自留在决定/证据记录中，并能相互引用；不混成一个删除总数。按原因展示的数量可能重叠，总排除数必须按唯一 cell_uid 计算。

例如某细胞因 OSP 模型建议 drop，直到 cross-sample.finalize 才实际被过滤：实际排除步骤记 cross-sample.finalize，决定来源引用 OSP 提案。zoom-in 中 HSP/JUN 主导且被判定为解离应激的亚群则在 zoom-in 应用步骤记录解离应激原因，不只留一个“remove”。

## 每个步骤验收时对账

对该步骤实际接收的细胞集合执行：

**输入 cell IDs = 输出保留 cell IDs ∪ 本步实际排除 cell IDs**，两部分不得重叠，不允许未知输出、重复归属或缺失细胞。

分流步骤按所有输出子集合的并集对账；汇合步骤按所有必需分支的结果和账本对账。失败、等待或未完成不是排除理由；分支未齐不能伪造已完成守恒。未排除任何细胞也记录步骤摘要：input 与 retained 相等，excluded 为 0。

跨步汇总沿当前有效版本的来源链追溯，不能混合不同重算版本。重试和重复通知不重复计数；一个步骤有多个过滤动作时保留各动作来源，同一细胞的多原因在本步汇总成一条记录。

## 保存与职责

Worker 在过滤发生时生成记录，将输出矩阵、账本、数量摘要放进同一个可验收结果；全部写完、回读对账成功后，Coordinator 才接受完成收据。账本丢失或理由为空时该步不能标记完成。大表通过文件引用交接，不集中加载到 Coordinator 内存。

Agent 负责按提交 schema 给出原因和证据；程序展开群体/样本决定对应的 cell IDs 并检查数量，不能让模型手工列数百万细胞。Scheduler 无须理解生物学删除原因。

报告可按阶段、原因、样本/谱系展示排除数量，并提供逐细胞记录。既有生产记录是否全部满足本契约需在实施时逐项验证，本文件不代表历史缺账已补齐。
