Per-sample / OSP：按样本计算，模型等待不占 pool

类型说明：「模型推理」指调用语言模型进行规划、判断或注释；「程序执行」指按代码完成数值计算、校验、查询、读写和结果应用，可使用 CPU 或 GPU。模型发起的工具调用仍属于程序执行；这些标注不增加调度步骤。

目的：样本 A 等待模型注释时，样本 B、C 以及其他数据集继续计算。每个完整实验样本是一块 OSP 数值任务，QC、聚类、DEG 连续执行，不分别排队。

设计草案，尚未实现或部署。Per-sample 通常在 round 1 之前执行；后续 cross-sample → ZMIP 的迭代不意味着每轮重新跑 OSP。这里的 sample 是有证据支持的完整实验池/文库，不能直接用细胞类型、实验条件或 Organize 的器官分组代替。

细胞排除记账〔程序执行〕

子集准备的显式排除、OSP 各个 QC 过滤动作都逐细胞记录原因，汇总为本步排除账本。模型 drop 仅保存提案，实际应用后才计入排除；不能提前计数。QC 全空或极小样本也必须交代每个输入细胞的去向，不能仅写“skipped”。

每次过滤 → 记录 cell IDs、原因和证据 → 与输出一起保存并核对细胞守恒。这是步骤内的必做环节，不新增排队任务。无排除也记录零排除摘要；账本未通过验收，该步不能完成。详见 统一细胞排除账本。

直接使用 Organize 确认的实验映射

已确认：样本识别、实验完整性与 analysis unit 拆分兼容性统一在 Organize 完成。Per-sample 不再设置样本确认 模型，也不重新裁决 Organize 的结果；仅核对交接版本、文件和 cell IDs 与确认映射是否一致。

① 准备样本子集〔程序执行〕 → ② OSP 计算〔程序执行〕 → ③ 注释〔模型推理〕 → ④ 应用并保存注释〔程序执行〕。

执行块类型连续完成的工作与输出执行位置 / 粒度
① 准备样本子集
persample.partition		程序执行读取 Organize 已确认的样本映射，核对文件与版本、cell IDs、样本数量是否一致；沿用上游来源和排除记录。按确定的 cell IDs 写出有限批次的样本子集、输入名单和请求凭据。不重新推断实验边界，不重复做科学完整性裁决。Pool 程序执行；共享读取、按有界批次准备
② 单样本 OSP 计算
osp.compute		程序执行校验子集；执行 QC（含配置启用的 Scrublet / DecontX）、保留通过细胞、归一化、HVG、PCA、邻居图、Leiden、UMAP、DEG/PAGA 和必要证据图。保存计算检查点、QC 删除记录及模型所需证据，然后释放计算资源。Pool 程序执行；每个完整样本一个任务
③ 样本注释
osp.annotate		模型推理模型阅读固定版本证据，提出细胞标签与 QC action。需要补证据时进入下述工具回路。保存每次回复、工具结果和有效聚类版本；必须通过提交校验才能结束。此处 模型 负责细胞注释，不重新做 Organize 的样本划分。Agent Bridge 调模型；Coordinator 校验、推进；不持有完整 AnnData 等待
④ 应用注释并发布
osp.finalize		程序执行读取有效计算版本和接受的提案，应用标签及 keep/flag/drop 标记，写出 H5AD、提案、必要报告和完成收据；验收输入 cell IDs 与 QC 删除记录的对应关系。校验与写出都属于这一块。Pool 程序执行；每个样本，Coordinator 接受结果

这是共享子集准备一块 + 各样本执行三块。①单独存在是为了复用共享输入读取；一次只准备有限批次，不等所有子集写完才开始②，也不一次物化几百个大文件。小输入或单样本可在不跨 模型 边界的前提下融合①和②。

注释中的工具调用怎么处理？

生成工具请求〔模型推理〕 → 校验请求〔程序执行〕 → 查询或计算〔程序执行〕 → 保存结果〔程序执行〕 → 继续判断〔模型推理〕。工具等待与模型等待分别释放各自的执行容量；不会让整个 osp.annotate 挂在 Worker 上等待。

现有工具类型新设计中的执行方式
check_qc_scores / 读取已有证据程序执行如果已有紧凑表能直接回答，在服务内读取返回；需要重新扫描大量 obs 时才派一个有预算的证据任务。不额外占一个大矩阵 Worker。
check_genes程序执行需要读取表达矩阵时，提交一次 osp.evidence 计算，返回指定基因的统计表，释放资源后再继续模型；相同输入与查询可复用结果。
subcluster程序执行提交一次 osp.refine：对子群聚类并计算配套区分基因，作为一个连续任务。成功细分产生新的工作聚类版本，后续工具和最终提案必须引用新版本，不重新跑整个样本 QC。
submit_annotation程序执行Coordinator 执行现有提案校验；无效则返回具体错误，合法才推进④。校验不必单独排队。需要扫描矩阵的校验放在有预算的程序执行中。

不会为每个 cluster 默认创建一个独立 agent。先保留每个样本一个连贯注释上下文；并发主要来自多个样本、多个数据集。

程序执行内部不再继续拆

  • ②中的 QC、Scrublet、DecontX、PCA、邻居图、聚类、UMAP 和 DEG 连续执行；日志保留各步名称，但不把日志中的每一步当成调度任务。
  • Scrublet、DecontX 等按配置和数据适用条件执行。单群体的 DEG/PAGA 跳过规则沿用现有实现，不为了画流程强制执行。
  • 样本之间并行，样本内不再按算法或 CPU/GPU 切换拆调度任务，OSP 的 DEG 也留在样本任务内。计算与模型等待仍分开；模型临时请求的补证据或子聚类沿用上述工具回路。
  • 复用已完成的 compute 检查点；注释失败只恢复注释或 finalization，不无条件从 QC 重算。版本化子聚类和工具结果的独立恢复仍需实现。

同一个样本任务，两套计算路径

路径类型执行方式
CPU：Scanpy程序执行沿用 CPU 数值流程及配套 QC 工具，在一个 Worker 内连续完成整个 osp.compute；不要求 GPU，本地 CPU Worker 同样可运行。
GPU：RAPIDS-singlecell程序执行适用的数值步骤采用经过验证的 GPU 实现；Scrublet / DecontX 等按各自适用实现执行，不假定所有 QC 都能转 GPU。需要 CPU 的部分在同一 Worker 内连续执行，整个样本仍只提交一个计算任务。

后端由配置指定，可选择自动 GPU 优先或显式 CPU/GPU。自动模式结合 RAM、VRAM、剩余机时、排队及搬运成本选择；没有合适 GPU 时允许 CPU 推进。显式 GPU 配置不能静默改成 CPU。任务按整样本峰值申请资源，多个样本是否同机并行由 Scheduler 按资源决定。

两套路径保持相同输入/输出、QC 账本与注释交接契约，不保证数值或聚类标签完全相同。保存实际后端、依赖版本、参数和随机设置；更换后端产生新的计算结果身份，不能套用旧聚类的模型决定。运行失败不能直接靠切 CPU 掩盖，须先记录原因并按配置恢复。

这是双后端的设计要求；各数值步骤的 GPU 适配和科学契约验证仍待实施，不代表当前 OSP 已具备完整 GPU 路径。

并发与必要的汇合点

情况处理
A 等 模型，B 的子集已经就绪B 可立即由 Scheduler 按资源匹配进入计算；A 不占计算名额。单 Worker 资源足够时可接多个样本任务。
模型服务慢，计算很快允许有限数量/字节的 computed 样本积压。上限控制磁盘和 Bridge 队列，不重新引入整个 dataset 的峰值预算准入。
个别样本故障独立样本继续；基础设施故障按限额自动重试，科学输入错误保留为待解决状态，不擅自排除该样本。
一个分析单元要进入 cross-sample保留必要的样本集合完整性：所有计划样本都有可接受的终态，且完成纳入判定后再整合。不能为了提前启动 cross-sample 静默漏掉慢样本或失败样本。其他分析单元照常推进。
Coordinator 崩溃，Worker 仍可用Worker 完成预先接受的有限计算并保存收据，随后等待；不能自行发起尚未授权的新模型回合。恢复后先对账再派活。

必须保留的科学边界

  • 信任 Organize：实验划分、完整性及跨来源合并证据在 Organize 写出前确认，结果随输入一起交付。Per-sample 不再根据完整 source_obs 重新判定组织方案，不把这项决定交给另一个 agent。
  • 仅保留交接一致性检查：确认映射缺失、文件版本变化或子集 cell IDs 不符时报告交接错误；修复或由 Organize 发布新版本后继续，不在 per-sample 私自修改样本划分。正常路径直接计算。
  • 两种删除不混淆：②中的规则 QC 会实际去除细胞并写 qc_removed.csv；③的 模型 drop 是建议，④仅应用标记，不在 OSP 注释处再物理删除，后续仍按既有 cross-sample 规则处理。
  • 空样本不当运行故障反复重试：沿用已验证的空样本结果契约与细胞账本。QC 后只剩 1–2 个细胞的既有停止和记录规则也要单独保留，不能伪造正常聚类或注释完成。
  • 排除规则可追溯：沿用 Organize 交付的排除记录（如有），保存 cell ID、原因和提出方；不为凑齐映射自行删除细胞。
  • 批次建议不是前置门槛：现有 _recommend_batch_key 是 advisory，失败不应阻塞 OSP。新设计将它作为可选 Bridge 工作，不能阻塞已经确认样本的计算，也不自动替换生效批次设置。

已有基础与需要修改的地方

已有：ecarsi/persample.py 的子集写出、ecarsi/sample_mapping.py 的实验映射保护、ecarsi/osp_stage.py 的 compute/annotation 恢复边界，以及 osp/cluster.py 的整样本数值流程。

核心改动：当前 osp/annotate.py:propose_annotation 先加载 clustered.h5ad，再等待 agent，并在同一进程处理工具与最终写出。应把这条路径分成持久模型交互、按需工具计算和最终应用，让等待回复时不再留着 AnnData。样本识别与实验完整性判断迁到 Organize；这里删除重复的样本确认模型调用，读取 Organize 的正式映射。迁移前的旧代码行为与本设计不同，不能把文档更新当作已完成部署。
