Review one lineage in a coherent session. First assign identity at Leiden resolution 1.0 (msp_leiden_r1.0), then assess quality at resolution 2.0 (msp_leiden_r2.0). Previous labels are context, not ground truth. Read annotation_status for accepted progress and the exact cross-tabulation; these partitions need not be nested.

Query this lineage's precomputed SQLite DEG using deg_lookup or bounded deg_sql, naming the clustering key explicitly. Use check_genes for missing expression evidence. A missing gene in top-ranked DEG is not evidence of absence. Read the lineage UMAP, QC and foreign-signal summaries. Foreign scores alone cannot establish contamination or misassignment; sample enrichment alone cannot justify deletion.

Read a lineage figure and call check_qc_scores early; these are required before the final proposals. Batch related marker questions: check_genes accepts up to 80 genes and cluster="" reads all clusters for the chosen key. Use bounded SQL across several clusters or genes rather than separate model round trips for each marker. If a marker is absent from top-ranked DEG, check its expression directly instead of repeatedly querying the same limited table. Gather enough evidence to decide, then submit; do not repeat unchanged evidence reads.

Submit complete 1.0 type proposals through submit_types, including evidence and supported merges. Type actions remain keep: removal and reassignment belong to quality review. Keep labels within this lineage. Submit complete 2.0 quality proposals through submit_quality. Each quality group explicitly partitions its cells by the intersecting 1.0 type IDs; enumerate each present intersection exactly once. This lets a decision target only the supported part of a mixed quality group without overwriting identity by a majority-parent assumption. Reassignment targets another planned coarse label, retains cells, and supplies a fine label; it does not cause re-embedding in the destination lineage this pass. Reassignment is for a clean population whose markers are another lineage's and which lacks this lineage's own markers; cells carrying this lineage's markers together with another lineage's are doublets: remove them with remove_reason doublet. The host rejects a reassignment whose cells still express this lineage's markers, and records one that repeats the previous round's move.

Default to remove for subclusters attributed to tissue dissociation or dying cells. Evaluate high mitochondrial fraction and HSP/JUN-dominated signatures against the assigned identity and comparable cells. This is not a rule to delete every cell expressing an individual marker. An exception requires explicit evidence that a population is a biological state to retain rather than the specified artifact/dying category. Do not retain a confirmed artifact merely by naming a stressed fine type. Removal reasons and evidence must identify the supported subcluster/intersection. An above-budget review checks evidence and scope under the same policy; it does not reverse the default policy.

Correct validation errors; an accepted submit_quality completes the session. For inadequate evidence, request only a necessary subcluster refinement, specifying target=type or quality. Use its new evidence version and annotation_status: resubmit only pending type_scope entries and then refresh quality. Quality refinement preserves accepted identity. If the configured refinement limit is reached, retain explicit uncertainty. Do not delete cells, merge labels or modify files yourself. The host applies accepted decisions, records exact cell exclusions and reassignments, and validates conservation.
