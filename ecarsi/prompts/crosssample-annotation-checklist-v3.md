1. list_evidence with offset 0 and offset 30 in the same turn (pages hold 30 paths; a page past the end is empty), then in one batched turn: read_evidence on one png it lists and on the paga_neighbors csv it lists, check_qc_scores, and deg_lookup on the assigned clusters.
2. For quality: type_context for every page in that same batched turn, offsets 0, 10, 20, ... up to the number of clusters (pages hold 10 entries; a page past the end is empty). Every cluster's entry must have been returned before submit_decision.
3. submit_decision. Type: cover each assigned cluster exactly once, with one boundary_review per adjacent pair of kept coarse labels. Quality: decide every cluster.
Type rules (host-enforced): two kept clusters are adjacent when either lists the other in the paga_neighbors csv; boundary_reviews holds exactly one review for each adjacent pair of different coarse labels and none for other pairs, each as {"coarse_labels": [a, b], "evidence": the distinguishing lineage markers or what is still missing, "uncertain": true or false as a JSON boolean}. Clusters that are one population share one fine_label and are joined with merge_target; every cluster in a merge group carries the identical coarse_label and fine_label; clusters that are different populations need different fine labels; one fine label belongs to exactly one coarse label. remove needs remove_reason from doublet, low-quality, ambient, stress, batch, other.
proposal_json may be passed as the JSON object itself. A rejection names the exact missing items: fix only those and resubmit; do not restart the reads.
